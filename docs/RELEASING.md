# نشر التحديث

بطاقة تشغيل مختصرة. التفاصيل في
[`docs/architecture_map.md`](architecture_map.md) (قسم *In-App Update Flow*).

## الفكرة

عند كل إقلاع تقارن نسخة التطبيق المثبتة شيئين:

| مصدر | يعطي | ماذا يعني |
|---|---|---|
| مستند Firestore `app_config/version` | `min_version` | **السياسة**: من لم يعد مسموحًا له بالتشغيل |
| أحدث إصدار في GitHub Releases | `latest_version` | **الواقع**: ما يمكن تنزيله فعلًا |

- نسختي أصغر من `min_version` → **إجباري**، ولا زر تخطّي عليه.
- نسختي أصغر من `latest_version` → **اختياري**، يظهر مرة واحدة وفيه «تخطّي الآن».
- غير ذلك → لا يظهر شيء.

إصدار GitHub يتقدّم على `latest_version` إن كان أعلى. أما `min_version`
فلا تأتي من أي مكان غير هذا المستند أو مفتاح `min_version` في Remote Config
(احتياطي يُقرأ إن كان المستند غائبًا أو فارغًا).

## نشر تحديث اختياري

**١.** رقِّم النسخة في `pubspec.yaml` — الرقم يجب أن يكون أعلى مما عند المستخدمين:

```yaml
version: 1.2.1+1
```

**٢.** انشر:

```powershell
$env:GITHUB_TOKEN = 'ghp_...'
.\tools\publish_release.ps1 -Notes '## ما الجديد
- إصلاح لوحة الإشعارات
- تسريع فتح الملفات الكبيرة'
```

السكربت يقرأ الرقم من `pubspec.yaml`، يبني، ينشئ الوسم `v1.2.1`، ويرفع الملف.
السطر `GitHub digest:` في آخر المخرجات هو البصمة التي سيتحقق منها التطبيق.

**٣.** انتهى. لا شيء آخر مطلوب.

> `-Notes` هو النص الذي يظهر في صفحة التحديث تحت «الإصدار الجديد».
> إن تركته فارغًا لن تعرض الصفحة قائمة تغييرات: `-Notes` بلا قيمة يعني نشرًا بلا
ملاحظات.

## نشر تحديث إجباري

الخطوتان ١ و ٢ نفسهما، ثم:

**٣.** في Firestore ← `app_config` ← المستند `version`، اكتب:

| الحقل | القيمة |
|---|---|
| `min_version` | نفس الرقم المنشور، مثال `1.2.1` |
| `latest_version` | نفس الرقم (اختياري — GitHub يقدّم عليه) |

**٤.** احفظ. من هذه اللحظة يُحجب كل تطبيق نسخته أصغر، ولا يستطيع التخطّي.

### تحذير قبل الرفع

`min_version` **لا يعود تلقائيًا**. رفعه إلى `1.2.1` يغلق أيضًا كل من هو على
`1.1.0` و`1.0.0`، حتى لو كان تحديثهم اختياريًا ويلائمه. ارفعه فقط حين تكون
النسخة الجديدة إلزامية فعلًا: خطأ أمني، أو خلل يفسد البيانات.

**للتراجع:** أعد `min_version` إلى رقم أقل. لا يحتاج الأمر نشرًا جديدًا.

## أخطاء شائعة

| ما تراه | السبب الحقيقي |
|---|---|
| لا يظهر لأحد | الرقم المنشور ليس أعلى من نسختهم. انشر `1.3.0` وأنتم على `1.2.0`. |
| «هذا الإصدار لم يُرفق به ملف تنصيب» | `latest_version` أعلى من الإصدار المنشور فعلًا في GitHub، فليس هناك ملف يُنزَّل. |
| فشل النشر: الوسم موجود | لم تُرقِّم النسخة. احذف الوسم، أو انشر الرقم التالي. |
| الجميع محجوب بعد إصدار اختياري | `min_version` ما زال على رقم أعلى من المنشور. |

## الأدوات

- **`tools/publish_release.ps1`** — البناء والنشر إلى GitHub Releases.
  يحتاج `GITHUB_TOKEN` بصلاحية `contents: write`، وInno Setup 6 مثبّت.
  `-SkipBuild` لإعادة رفع نفس الملف بعد فشل في الرفع، بلا إعادة بناء.
- **`tools/publish_installer_doc.mjs`** — يكتب `latest_version` في Firestore
  تلقائيًا. أداة مساعدة لتجنّب فتح الكونسول؛ اختيارية، فإصدار GitHub يقدّم عليها
  بنفسه. **ملاحظة:** تعليقها العلوي يقول إن `publish_release.ps1` يناديها بعد
  نجاح الرفع، وهذا غير صحيح — لا يوجد أي استدعاء لها في السكربت. شغّلها يدويًا إن
  احتجت إليها، وتحقّق من الأمر قبل الاعتماد عليها.
